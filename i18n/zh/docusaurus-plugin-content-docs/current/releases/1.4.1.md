# ZotFlow 1.4.1

一个小版本，修的是 ZotFlow 一直悄悄记错的东西：被截去一半的引用键，以及提取得
乱七八糟的笔记标题。它不改变你的使用方式，改变的是最终存下来的内容。

升级是安全的。已有的 source note 不会改名，已经插入到笔记里的引用也不会被改动。
下次同步后笔记标题和引用键会有一次性的变化，文末有说明。

## 修复

- **引用键不再被截断。** 像 `smith-2020` 这样的键之前只存下 `smith`——从第一个
  连字符或点开始的部分全部丢掉。Better BibTeX 生成带连字符的键是家常便饭，所以
  这个问题影响面不小。现在能完整读出来了。
- **笔记标题只取第一段。** 多段落的笔记以前会把所有段落挤成一行当标题，现在到
  第一段就停。
- **笔记标题里的转义字符正常显示。** 标题为 `Tea &amp; Coffee` 的笔记现在显示为
  `Tea & Coffee`。
- **以格式开头的笔记不再丢标题。** 如果笔记开头有大量标记或空白，标题可能变成空
  的，或者被截得什么都不剩。
- **指向相关条目的链接指向笔记的真实位置。** 模板从 Zotero「相关」条目生成链接
  时，现在用的是笔记实际所在的位置，而不是路径模板算出来的位置。只要笔记被移动
  过、改过名，或者为避免文件名冲突加过 `(1)` 后缀，这两者就会对不上。设置里的引
  用预览也有同样的问题。
- **插件的测试覆盖大幅增加**——同步、模板、笔记、标注、阅读器桥接、附件缓存和
  WebDAV——以及写这些测试过程中发现并修掉的问题。

## 你会看到一次的变化

下次同步会重新记录它处理到的条目的标题和引用键。有两点值得知道：

- **你的 source note 不会被改名。** ZotFlow 是靠 frontmatter 里的 `zotero-key`
  找笔记的，不是靠重新计算文件名，所以即使引用键变了，笔记还待在原地。只有从现
  在起新建的笔记才会用完整的键做文件名。
- **已经写进笔记的引用不会被重写。** 如果你在这个版本之前插入的是 `[@smith]`，
  它就一直是 `[@smith]`；之后新插入的会是 `[@smith-2020]`。

:::note[如果你用 Pandoc 导出]
第二点对你有影响。你的 `.bib` 文件里一直是完整的键（`smith-2020`），也就是说
ZotFlow 之前插入的短键 `[@smith]` 本来就对不上。这一版修好了新插入的，但没法回头
修已经写进笔记里的那些——它们需要你自己查找替换，或者重新插入一遍。
:::
